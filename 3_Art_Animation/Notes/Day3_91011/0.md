# % Vs $
Small correction: it's the other way around. You don't need `%` for an immediate child. `$` is what you use for a direct child, and `%` is for a node that has been marked as a Unique Name, wherever it sits in the scene.

## Notes: `$` vs `%`

**`$` (path lookup)**
- Shorthand for `get_node("path")`.
- The path is relative to the node holding the script.
- Immediate child: `$Timer`
- Deeper node: `$Root/OnlinePanel/OnlineContainer/IpInput`, where each level is separated by `/`.
- Needs no setup in the editor.
- It breaks if you rename or move any node along the path.

**`%` (unique name lookup)**
- Shorthand for `get_node("%Name")`.
- The node must have **Access as Unique Name** enabled (right-click in the Scene dock, which shows a green `%` badge).
- It finds the node anywhere inside the same scene, at any depth.
- The path doesn't matter, so you can move the node between containers and the script still works.
- It breaks only if you rename the node or remove the unique flag.
- Names must be unique within that scene.

## Quick comparison

| | `$` | `%` |
|---|---|---|
| Editor setup | None | Right-click, Access as Unique Name |
| Depends on tree position | Yes | No |
| Depends on node name | Yes | Yes |
| Best for | Direct children (`$Timer`, `$Sprite2D`) | UI nodes buried in containers |
| Reaches into instanced child scenes | No | No |

## Rule of thumb
- Short, stable path → `$`
- Deeply nested or likely to be rearranged → `%`

## Answer to my earlier question
If you move `IpInput` directly under `Root`, `%IpInput` still works, because the path doesn't matter. The `$Root/OnlinePanel/OnlineContainer/IpInput` version breaks, because that path no longer exists.
