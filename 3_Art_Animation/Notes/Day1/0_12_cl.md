### 0.2 Aseprite one-time setup

1. **File → New**: Width 32, Height 32, Color Mode **RGBA**, Background **Transparent**. This is your palette-builder file.
2. Build the 12 colors (table below): double-click a swatch in the palette bar to set its color. Add swatches with the **+** button. You will also add 1 water-blue for the health bar (13th swatch).
3. Palette menu (the ≡ icon beside the palette) → **Save Palette…** → `art_source/palette/keep_ostriching.gpl`.
4. In every new file from now on, load it: palette menu → **Load Palette…** → pick that `.gpl`.
5. In each character file, make the guide layer: **Layer → New Layer**, name it `guide`, draw the ground line, center column and headroom line. Hide it with the eye icon before export. Hidden layers are not exported.
6. Turn on **View → Show → Pixel Grid** so each pixel is visible while you work.
7. Set frame timing: right-click a frame number in the timeline → **Frame Properties** → Duration (ms).
8. Tag a range: select the frame range in the timeline → **Frame → Tags → New Tag** → name it → OK.
9. Onion skin: click the onion-skin button in the timeline header.

### 0.4 Aseprite export recipes

**Recipe A: multi-frame sheets (ostrich, cactus)**
1. **File → Export Sprite Sheet**.
2. **Layout tab:** Sheet Type = **Horizontal Strip**. Border Padding, Spacing and Inner Padding = **0**. **Merge Duplicates = OFF** (if on, identical frames collapse and your frame numbers break). Depending on your Aseprite version, Merge Duplicates and Trim sit in a Borders section or tab, so check every tab.
3. **Sprite tab:** Layers = **Visible layers**. Frames = **All frames**.
4. **Borders:** Trim Sprite OFF, Trim Cells OFF.
5. **Output tab:** tick **Output File**, set the `.png` path. Leave JSON Data off.
6. Click **Export**. Check the PNG size against the table (ostrich must be **416×32**).

**Recipe B: single images (title, panel, hp_\*, menu_bg)**
**File → Export As…** → file name → `.png` → Export, scale **1×**.

**Recipe C: buttons (3 frames → 3 PNGs)**
**File → Export As…** → name `ui_btn_{tag}.png` → Export. If your Aseprite version doesn't split it, export each frame as its own file by hand (`ui_btn_normal.png`, `ui_btn_hover.png`, `ui_btn_pressed.png`).

## PART 2: OSTRICH

### 2.1 Canvas anatomy: 32×32, facing right only

Left movement uses `flip_h`, so never draw a left-facing frame. Coordinates are (x, y) from the top-left. On your `guide` layer draw and later hide:
- Ground line: **y = 31**. Feet bottoms touch it on every grounded frame.
- Center column: **x = 16**.
- Headroom: head top starts at y = 3, leaving 3 px for jump stretch.

| Part | Idle (frame 0) position | Color |
|---|---|---|
| Body (oval) | x 8–22, y 14–23 | feather dark #2 with light #3 on top-left |
| Tail plume | x 4–8, y 13–18 | feather dark #2 |
| Wing patch | x 11–16, y 15–20 | feather light #3 |
| Neck | x 21–23, y 5–14 | skin #4 |
| Head | x 22–27, y 3–7 | skin #4 |
| Beak | x 27–30, y 5–6 | orange #5 |
| Eye | single pixel at (24, 4) | outline #1 |
| Near leg | x 17–18, y 23–31 | skin #4 |
| Far leg | x 12–13, y 23–31 | **darker skin** (mix #4 and #1), so crossing legs read |
| Feet | 3 px toes pointing right, y 31 | orange #5 |

### 2.2 The 13 frames (all changes are relative to frame 0)

| # | Tag | Duration | Exactly what changes |
|---|---|---|---|
| 0 | idle | 400 ms | as in the table above |
| 1 | idle | 400 ms | body, tail, neck and head all down 1 px. Legs stay, the thigh becomes 1 px shorter |
| 2 | walk | 125 ms | **contact:** body down 1 px. Near foot forward at x 21–23, far foot back at x 8–10. Both feet on y = 31 |
| 3 | walk | 125 ms | **passing:** body up 1 px (y 13–22). Legs under body at x 14–16. Far leg lifted, foot at y = 29 |
| 4 | walk | 125 ms | **contact (mirror):** body down 1 px. Far foot forward, near foot back (swap the leg shades) |
| 5 | walk | 125 ms | **passing (mirror):** body up 1 px. Near leg lifted, foot at y = 29 |
| 6 | jump | 100 ms | body and neck stretched 2 px taller. Knees bent, both feet tucked up at y 26–27. Wing patch flicked 2 px up |
| 7 | fall | 100 ms | legs straight down and slightly apart, feet at y = 29. Wings raised, head tilted up 1 px |
| 8 | kick | 80 ms | **wind-up:** head and neck back 2 px, tail 2 px lower. Support leg planted at x 14–15. Kick leg bent behind the body, foot at x 6–8, y 24 |
| 9 | kick | 80 ms | **strike:** head forward **1 px** (beak tip at x = 31, the last pixel column). Kick leg fully horizontal at y 20–22, toes reaching x 29–31. Add 2 short speed lines behind the leg in sand-light #6 |
| 10 | kick | 80 ms | **recovery:** leg bent at the knee at x 20–22, y 24–26, foot lowering. Body re-centering, keeping a slight 1 px forward lean |
| 11 | plunge | 100 ms | **squash:** whole sprite 2 px shorter. Neck folded (head at y = 7), legs tucked tight, wing patch pulled against body |
| 12 | plunge | 100 ms | **dive:** body diagonal from about (6, 6) to (24, 24). Beak pointing down-right at (26–28, 26–29). Feet at the top-left, tail trailing |

Rules for the whole sheet:
- The **body outline never leaves** palette #1.
- In the walk, only the bob and legs move. If your head slides left and right, the walk looks like skating.
- Frame order must be exactly 0 to 12.

### 2.3 Aseprite steps

1. Create `art_source/ostrich/ostrich.aseprite` (32×32, RGBA, transparent) and load the palette.
2. Draw frame 0 fully with outline on one layer. Fill it solid black temporarily to run the **silhouette test** (is it still clearly an ostrich?), then undo.
3. Create the other frames: select a frame in the timeline, right-click → **Duplicate Frame**. Duplicate frame 0 up to 13 frames total and edit only what changes (table above).
4. Turn on onion skin while drawing the walk and kick.
5. Set each frame's duration (Frame Properties), then add the tags `idle`, `walk`, `jump`, `fall`, `kick`, `plunge` over their frame ranges.
6. Hide the `guide` layer. Save.
7. Export with **Recipe A** to `assets/art/ostrich/ostrich.png`. Check that it is **416×32**.

### 2.4 Godot: `scenes/player/Player.tscn`

```
Player (CharacterBody2D)
├─ Sprite (AnimatedSprite2D)    → offset (0, 0), centered
├─ Body (CollisionShape2D)      → rectangle 12 × 26, position (0, 3)
└─ KickHitbox (Area2D)          → monitoring OFF by default
   └─ Shape (CollisionShape2D)  → rectangle 12 × 6, position (10, 5)
```

Build order:
1. Open `Player.tscn` and add the `AnimatedSprite2D` (keep the ColorRect for now, for comparison).
2. Select it → Inspector → **Sprite Frames → New SpriteFrames** → click it → save as `resources/spriteframes/ostrich_frames.tres`.
3. In the SpriteFrames bottom panel, rename `default` to `idle`, then add `walk`, `jump`, `fall`, `kick`, `plunge` with the **Add Animation** button.
4. For each animation, click the **grid icon (Add Frames from Sprite Sheet)** → pick `ostrich.png` → Horizontal = **13**, Vertical = **1** → select the frame numbers from the table below (Ctrl+click for multiple) → **Add Frames**. Verify the order.
5. Set **Speed (FPS)** and the **Loop** toggle:

| Animation | Frames | FPS | Loop |
|---|---|---|---|
| idle | 0, 1 | 2.5 | on |
| walk | 2, 3, 4, 5 | 8 | on |
| jump | 6 | 5 | off |
| fall | 7 | 5 | off |
| kick | 8, 9, 10 | 12 | off |
| plunge | 11, 12 | 10 | off |

Math check: kick = 3 frames ÷ 12 FPS = **0.25 s**. Your kick state timer must match this.

6. Add the `CollisionShape2D` (rectangle **12×26** at position (0, 3)) and your `KickHitbox` Area2D with a **12×6** shape at (10, 5), monitoring off by default.
7. In `player.gd`, where the state changes, write your own `match` that picks the animation name from the state. The state machine decides, the sprite follows. Animation code must never change game behavior.
8. Flip horizontally by movement direction. When velocity is zero, keep the last facing (don't snap back to default).
9. Delete the ColorRect.
10. Run with two players. Each must animate independently.

**Why those collision numbers:** the sprite is centered at (16, 16). A 12×26 box at y = +3 puts its bottom exactly at the feet (+16), and it excludes the tail and beak. The kick leg reaches x 20–31, which is +4 to +15 from the center, at y 20–22 (+4 to +6), so the hitbox sits at +10, +5.

**Pitfalls:**
- `flip_h` flips only the sprite, **not** the hitbox. Decide how the hitbox mirrors with facing. Test by kicking left.
- Never enable the hitbox from the animation. Your state logic owns it.

**State → animation mapping (copy exactly):**

| State | Animation | Loop | Who ends it |
|---|---|---|---|
| IDLE | idle | yes | input change |
| WALK | walk | yes | input change |
| JUMP | jump | no (holds frame) | velocity turns downward |
| FALL | fall | no (holds frame) | landing |
| KICK | kick | no | **your timer = 3 ÷ 12 = 0.25 s** |
| PLUNGE | plunge | no (holds last frame) | landing |

Priority when several are true: **PLUNGE > KICK > JUMP/FALL > WALK > IDLE.**

**Ostrich done check:**
- Run two players in different states at the same time.
- Turn on **Debug → Visible Collision Shapes**, spam kick: the hitbox must be on only for the frames you chose.
- Kick facing left and facing right.
- Jump while walking: each frame must show jump or fall, never walk.
