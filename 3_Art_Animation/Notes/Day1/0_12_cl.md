## PART 1: ASEPRITE BASICS (simple English)

Menu names can change a little between versions. If you do not see one, look in the same menu for a similar name.

**1. Canvas and colors.** A canvas is a small grid of squares (pixels). Turn on **View → Show → Pixel Grid** to see them. Pick colors only from your palette.

**2. Timeline (bottom of the screen).** Each column is one **frame** (one picture). Each row is a **layer** (a sheet of glass you draw on). A frame is one picture in the animation, like one page in a flip book.

**3. Make a new frame.** Right-click a frame number → **Duplicate Frame**. You get a copy. Change only what moves.

**4. Layers.** Use two layers: `body` (the drawing) and `guide` (ground line, center line). Lock `guide` with the padlock. Hide `guide` with the eye icon **before you export**. Hidden layers are not exported.

**5. Onion skin.** Turn on the onion-skin button in the timeline header. It shows the last frame faintly, so you can see how far a foot moved.

**6. Duration.** Right-click a frame → **Frame Properties** → Duration (ms). 100 ms = 10 pictures per second. You can select many frames at once with Shift+click.

> Aseprite durations are only for **previewing**. In Godot you type your own speed (FPS). FPS = 1000 ÷ ms. So 125 ms = 8 FPS.

**7. Tags.** A tag is a name for a group of frames, like `walk`. Select the frames → **Frame → Tags → New Tag** → type a name. Press **Enter** to play the animation and look at it.

**8. Export a sprite sheet** (all frames in one row). Use this for the ostrich and the cactus.
1. **File → Export Sprite Sheet**.
2. **Layout tab:** Sheet Type = **Horizontal Strip**. Border Padding, Spacing, Inner Padding = **0**. **Merge Duplicates = OFF** (if ON, frames that look the same collapse and your frame numbers break). In some versions this box is in another tab, so check every tab.
3. **Sprite tab:** Layers = **Visible layers**, Frames = **All frames**.
4. **Borders:** Trim Sprite OFF, Trim Cells OFF.
5. **Output tab:** tick **Output File** and choose the `.png` path. JSON off.
6. Click **Export**. Check the width: **number of frames × canvas width**.

**9. Export one picture** (tiles, icons): **File → Export As…** → name → `.png` → scale **1×**.

**10. Practice drill (15 minutes, before the ostrich).**
1. New file 16×16, load palette.
2. Frame 1: draw a 6×6 ball at x 5–10, top at y = 1.
3. Make 3 more frames. Ball top at y = 5, y = 9, y = 5.
4. Add a tag `bounce` on all 4 frames. Press Enter.
5. Export a sprite sheet. It must be **64×16**.
6. Keep this PNG. You will test the ways in Part 5 with it.

### 2.2 Old way in Godot: Sprite2D + your own code

Idea: one picture node (`Sprite2D`) and a small script that changes the frame number by itself. You are building a tiny animation player. No built-in animation node is used.

**Build the node:**
1. Open `scenes/player/Player.tscn`.
2. Right-click `Player` → **Add Child Node** → `Sprite2D`. Rename it `Sprite`.
3. Drag `ostrich.png` into **Texture** in the Inspector.
4. Inspector → **Animation** group: **Hframes = 13**, **Vframes = 1**. Now **Frame** picks one picture from the strip.
5. **Check before any code:** click the **Frame** number and set it to 0, 1, 2 … 12 one by one. Every number must show the picture you expect. If not, your sheet or Hframes is wrong. Fix this first.
6. Keep the old ColorRect for now, to compare. Delete it at the end.

**Add the collision nodes:**
```
Player (CharacterBody2D)
├─ Sprite (Sprite2D)            → Hframes 13, Vframes 1
├─ Body (CollisionShape2D)      → rectangle 12 × 26, position (0, 3)
└─ KickHitbox (Area2D)          → Monitoring OFF
   └─ Shape (CollisionShape2D)  → rectangle 12 × 6, position (10, 5)
```
Why these numbers: the sprite center is (16, 16). A 12×26 box at y = +3 ends at the feet and skips the tail and beak. The kick leg reaches x +4 to +15 at y +4 to +6, so the hitbox sits at (+10, +5).

**Attach the animation script:**
1. Right-click `Sprite` → **Attach Script** → path `res://scripts/ostrich_sprite.gd` → **Create**.
2. Paste this:

```gdscript
extends Sprite2D

# Frame numbers in ostrich.png (0 to 12), speed in frames per second.
const ANIMS := {
	"idle":   {"frames": [0, 1],       "fps": 2.5,  "loop": true},
	"walk":   {"frames": [2, 3, 4, 5], "fps": 8.0,  "loop": true},
	"jump":   {"frames": [6],          "fps": 5.0,  "loop": false},
	"fall":   {"frames": [7],          "fps": 5.0,  "loop": false},
	"kick":   {"frames": [8, 9, 10],   "fps": 12.0, "loop": false},
	"plunge": {"frames": [11, 12],     "fps": 10.0, "loop": false},
}

var current := "idle"
var _time := 0.0   # seconds since this animation started

func play(anim: String, restart := false) -> void:
	if anim == current and not restart:
		return                 # already playing, do not restart it
	current = anim
	_time = 0.0
	_show_frame()

func _process(delta: float) -> void:
	_time += delta
	_show_frame()

func _show_frame() -> void:
	var data: Dictionary = ANIMS[current]
	var count: int = data["frames"].size()
	var step := int(_time * data["fps"])      # which picture of this animation
	if data["loop"]:
		step = step % count                   # go around again
	else:
		step = mini(step, count - 1)          # stop on the last picture
	frame = data["frames"][step]

# For display only. Gameplay must use its own timer.
func is_finished() -> bool:
	var data: Dictionary = ANIMS[current]
	return not data["loop"] and _time * data["fps"] >= data["frames"].size()
```

**How it works:** `_time * fps` tells how many pictures should have passed. Cut to a whole number with `int()`. That number picks an entry in the `frames` list. Kick = 3 pictures ÷ 12 FPS = **0.25 s**.

**Use it in `player.gd`:**
1. At the top: `@onready var sprite: Sprite2D = $Sprite` and `@onready var kick_shape: CollisionShape2D = $KickHitbox/Shape`.
2. Where your state changes, write your own `match` on the state and call `sprite.play("idle")`, `sprite.play("walk")` and so on. For a new kick, use `sprite.play("kick", true)` so spamming kick restarts it.
3. Facing:

```gdscript
func _set_facing(dir: int) -> void:
	if dir == 0:
		return                          # no input: keep last facing
	sprite.flip_h = dir < 0             # flips the picture only
	kick_shape.position.x = 10 * dir    # moves the hitbox to the same side
```
4. Delete the ColorRect. Run with two players. Each one must animate on its own.

**State → animation:**

| State | Animation | Loop | Who ends it |
|---|---|---|---|
| IDLE | idle | yes | input change |
| WALK | walk | yes | input change |
| JUMP | jump | no (holds frame) | velocity turns downward |
| FALL | fall | no (holds frame) | landing |
| KICK | kick | no | **your timer, 0.25 s** |
| PLUNGE | plunge | no (holds last frame) | landing |

Priority when several are true: **PLUNGE > KICK > JUMP/FALL > WALK > IDLE.**

**Golden rule:** the picture follows the game state. The game state never follows the picture. Your state code turns the hitbox on and off. The animation never does.

**Ostrich checks:**
- Two players in different states at the same time.
- **Debug → Visible Collision Shapes**, spam kick: the hitbox is on only for 0.25 s.
- Kick left and right.
- Jump while walking: every picture is jump or fall, never walk.

## PART 4: TILESET (16 tiles)

### 4.1 Draw it

`art_source/tileset/sand_tileset.aseprite`: canvas **128×64** = 8 columns × 4 rows of **16×16** tiles.

1. **View → Grid → Grid Settings**: width 16, height 16. Turn on **View → Show → Grid** and **Snap to Grid**.
2. **Row 1** (columns 0–7):

| Column | Tile |
|---|---|
| 0, 1, 2 | **sand fill**, 3 variants. Fill #7, then scatter 4–6 specks of #6 and #8 (different spots in each) |
| 3 | **top edge** |
| 4 | **top-left corner** |
| 5 | **top-right corner** |
| 6 | **left edge** |
| 7 | **right edge** |

   Edge rule: on the side that touches air, draw a 2 px light line (#6), then a 1 px dark line (#8) just inside it. Fill the rest with #7 and a few specks. For corners, draw both edges and erase the 3 outermost corner pixels, for example (0,0), (1,0), (0,1).
3. **Row 2:** copy row 1, then swap #7 to #8 and #6 to #7. This is deep, darker sand.
4. Rows 3 and 4 stay empty for now.
5. Export (**Export As…**, 1×) to `assets/art/tileset/sand_tileset.png`. Size must be **128×64**.

Edges must meet without a seam. Place two sand-fill tiles side by side in Aseprite and look.

### 4.2 Old way in Godot

The old way for tiles is to place one `Sprite2D` per tile by hand. It works, but a level of 500 tiles means 500 nodes. For tiles, Godot's tile system is the normal tool. Do it like this:

1. Open your level scene. Right-click the root → **Add Child Node** → **TileMapLayer** (older tutorials call it TileMap).
2. Inspector → **Tile Set → New TileSet**. Click it to expand.
3. Set **Tile Size = 16 × 16**.
4. **Physics Layers → Add Element** (this adds collision).
5. Open the **TileSet** panel at the bottom. Drag `sand_tileset.png` into it. Click **Yes** when it asks to create tiles automatically.
6. Click the **Select** tab. Select a solid tile → **Physics → Physics Layer 0** → in the viewport, draw the collision square (use the 16×16 full square). Repeat for every solid tile (select several tiles at once with Ctrl+click).
7. Switch to the **TileMap** panel → **Paint** tool → pick a tile → click in the level to paint.
8. Save the TileSet as `resources/tilesets/sand_tileset.tres` (Inspector → click the TileSet → Save As).
9. Test: the ostrich must stand on the tiles and must not fall through.

Pitfall: if the player walks on a seam, a tile is missing its collision shape.

## PART 5: ALL THE WAYS TO ANIMATE IN GODOT

These apply to the ostrich, snakes, eagle, cactus, rocks and everything else. We used way 1 above. Try the others on your bouncing ball from the drill.

### Way 1: Sprite2D + frame number + your own code (the old way)
- Nodes: `Sprite2D` (Hframes/Vframes set).
- Good for: understanding how animation really works. Full control of timing.
- Costs: you write and fix the animation code yourself.
- Steps: Part 2.2.

### Way 2: one PNG per frame, swap the texture in code
1. In Aseprite: **File → Export As…**, name `ball_{frame}.png`, export all frames.
2. In Godot add `Sprite2D`. In a script:

```gdscript
extends Sprite2D

var frames: Array[Texture2D] = [
	preload("res://assets/art/ball_0.png"),
	preload("res://assets/art/ball_1.png"),
	preload("res://assets/art/ball_2.png"),
	preload("res://assets/art/ball_3.png"),
]
var _time := 0.0

func _process(delta: float) -> void:
	_time += delta
	texture = frames[int(_time * 10.0) % frames.size()]
```
- Good for: a few frames, quick tests, frames of different sizes.
- Costs: many files, many `preload` lines.

### Way 3: Sprite2D + AnimationPlayer
1. `Sprite2D` with Hframes/Vframes set.
2. Add `AnimationPlayer`. Bottom panel → **Animation → New** → name `bounce`.
3. Length 0.4, Step 0.1, Loop on.
4. **Add Track → Property Track** → Sprite2D → `frame`.
5. Right-click the track at 0, 0.1, 0.2, 0.3 → **Insert Key** → values 0, 1, 2, 3.
6. Track settings → **Update Mode = Discrete** (the frame number must jump, not slide).
7. Click **Autoplay**, run.
- Good for: one timeline that also plays sounds, moves things, calls functions.
- Costs: more setup. If it also turns the hitbox on, it can disagree with your state machine. Keep hitbox logic in your state code.

### Way 4: AnimatedSprite2D + SpriteFrames (Godot's built-in helper)
1. Add `AnimatedSprite2D`. Inspector → **Sprite Frames → New SpriteFrames**.
2. Bottom panel: rename `default` to `bounce`.
3. Click the **grid icon** (Add Frames from Sprite Sheet) → pick the PNG → Horizontal 4, Vertical 1 → select frames 0–3 → **Add Frames**.
4. Set **FPS 10**, **Loop on**, click **Autoplay on Load**.
5. In code: `$AnimatedSprite2D.play("bounce")`.
- Good for: fastest setup. Many animations on one node. Per-frame timing.
- Costs: you learn less about what happens inside.

### Way 5: Aseprite importer add-on
- Godot's **AssetLib** tab has add-ons that read `.aseprite` files directly, with tags and durations. I cannot check the current version, so read its page before you use it.
- It needs the `.aseprite` file inside the project, which clashes with `art_source/.gdignore`.
- Learn way 1 and way 4 first. Then you will understand what the add-on does for you.

### Way 6: AtlasTexture (show one frame from a sheet)
- On a `TextureRect` or `Sprite2D`: **Texture → New AtlasTexture** → **Atlas** = your sheet → **Region** = x, y, width, height of one frame. Frame 3 of a 32 px sheet = x 96, y 0, w 32, h 32.
- Good for: icons and single pictures cut from one sheet.
- Costs: it is not an animation by itself.

### Way 7: no frames, move it with code (Tween)
- For squash, stretch, bounce, fade and hover effects. Example: scale the ostrich to (1.2, 0.8) for 0.1 s on landing:

```gdscript
var t := create_tween()
t.tween_property(sprite, "scale", Vector2(1.2, 0.8), 0.05)
t.tween_property(sprite, "scale", Vector2.ONE, 0.1)
```
- Good for: extra life with no extra drawing. Costs: only simple motion.

### Tiles and backgrounds
- **TileMapLayer + TileSet** (what we did): level ground and walls. A TileSet tile can also have animation frames (select a tile → Animation columns/frames in the TileSet panel).
- **Sprite2D per tile**: works for 5 tiles, bad for 500.
- **TextureRect, Stretch Mode = Tile**: repeating floor or sky pattern.
- **Parallax2D** (Godot 4.3+) with a `Sprite2D` or `TextureRect` child: scrolling background layers. Backgrounds are **576×324**.

### Which way for what

| Thing | Best way | Also possible |
|---|---|---|
| Ostrich | Way 1 (learning), then Way 4 | Way 3 |
| Snakes (you do) | Way 1 or Way 4 | Way 3 |
| Eagle (later) | Way 4 | Way 3, Way 1 |
| Cactus | Way 1 (2 frames) | Way 4 with autoplay |
| Rocks | one `Sprite2D`, no animation | Way 6 if from a big sheet |
| Water prop | Way 1 or Way 4 | Way 3 |
| Tileset | TileMapLayer | Sprite2D per tile (not recommended) |
| Backgrounds | Parallax2D + `Sprite2D` | `TextureRect` set to Tile |
| Effects (dust, speed lines) | Way 4 or Way 7 | Way 3 |
| Icons | Way 6 | one PNG each |
